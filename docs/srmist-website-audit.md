# SRMIST website audit and redesign backlog

5 November 2026 · Official public site vs. redesign working tree based on commit `211f053`

The redesign already has a distinctive campus experience, a shared navigation system, eight server-rendered pages and an assistant. Its biggest gap is task completion. An applicant should be able to locate the right programme and intake. A current student should be able to locate the right portal, exam schedule or support service. A member of the public should be able to reach an authoritative disclosure. These journeys deserve direct links and maintained records.

## Evidence and scope

- Inspected the live homepage in a browser, including its screenshot, accessibility tree, markup, five mega-menu groups, utility navigation and footer. Opened and sampled the six official pages listed below. The [existing repository inventory](srmist-inner-pages.md) records 126 successful on-site destinations across the homepage navigation. That is prior inventory evidence. This audit rechecked the homepage and representative pages. It did not freshly validate every destination, document, deep programme page or external portal.
- Reviewed the redesign templates, generated markup for all eight routes, navigation, assistant, crawler, local server and Vercel configuration. Exercised browser search and mobile menu dismissal. Checked the local HTTP responses and ran build and assistant tests. The test rerun passed all 37 using the test suite's local mock, after sandbox loopback restrictions were lifted. No live Gemini request was needed.
- The official homepage loaded in the interactive browser, while the research fetch received 403 and shell DNS could not resolve the domain in this environment. Official production headers, TLS settings, authentication internals, WordPress patch status and real-user performance remain unverified. The official security observations are passive. The redesign security findings are based on source and the local preview. Production edge rules and deployment configuration outside this repository remain unverified.
- Official sources inspected in the browser: [homepage](https://www.srmist.edu.in/), [Programme Finder](https://www.srmist.edu.in/program-finder/), [Students](https://www.srmist.edu.in/students/), [Examinations](https://www.srmist.edu.in/controller-of-examinations/), [Admission India](https://www.srmist.edu.in/admission-india/), [International Relations](https://www.srmist.edu.in/ir/), [Public Self-Disclosure](https://www.srmist.edu.in/ugc/).

## Redesign design, accessibility and code

- **Keep the campus storytelling and make it optional.** The sampled mobile homepage gave Admissions a visible, high-contrast CTA. The cinematic headline gives little immediate information about the institution or campus coverage. Add an institutional descriptor and direct entry to programmes and student services near the first screen. Use genuine, approved campus photos on factual pages. Keep illustrations clearly identified as concepts.
- **Keep the homepage usable without animation or WebGL.** The intro supports Escape, a skip button, session gating and reduced motion. Verify that the skip is reachable immediately, focus returns to useful content, and normal content appears with failed scripts, no storage, slow network or no GPU. Add a plain-text campus directory outside the 3D interaction.
- **Add a skip link to every template.** Generated HTML had one H1 per page and the static scan found no duplicate IDs or unresolved internal fragment targets. It found no skip-to-content link. Provide one at the first keyboard stop and verify that focus moves to main content. Evaluate WCAG 2.2 AA with manual keyboard and screen-reader testing alongside automated checks. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- **Make names and focus work in context.** Replace repeated labels such as “Official SRMIST resource” in the renderer with names like “Search the Central Library catalogue.” Test header focus, Escape, mobile menu opening/closing, sticky elements, search status announcements, 320 CSS px reflow, 200% zoom, touch targets and the assistant's focus behavior. Check the light and dark image-backed states, motion reduction, keyboard map alternatives and PDF reading order. The browser confirmed Escape closed the redesign mobile menu.
- **Search actual content.** In the browser, hostels, library and scholarships each returned one match. Exam and B.Tech returned none. The current search derives labels from desktop navigation and uses ASCII normalization. Index page titles, programmes, departments, services, aliases and announcements. Give “B.Tech,” “BTech,” “exams,” “results,” common acronyms and spelling variants predictable results. Support a normal results URL and an accessible no-match state. [Navigation code](../navigation.js)
- **Prepare for more than eight routes.** Build outputs eight static HTML pages and a browser asset allowlist. The renderer interpolates repository-authored strings and URLs into HTML. If content comes from a CMS or import, introduce escaping, schema validation and safe URL handling at that boundary. Add automated link/fragment checks, route redirects from the official migration inventory, production canonical tags, XML sitemap, robots policy and a helpful 404. Keep prototype previews out of indexing. [Renderer](../render-pages.mjs) · [Build](../build.mjs)
- **Set a performance budget.** The vendored Three.js module is about 1.33 MB on disk before transfer compression. The workspace also holds an 8.57 MB concept GLB, outside the current build's asset allowlist. Keep large 3D assets and media off the initial path, provide a static fallback, and measure admissions, catalogue and home on a low-end mobile profile. Target p75 LCP ≤ 2.5 s, INP ≤ 200 ms and CLS ≤ 0.1 once field data exists. [Core Web Vitals](https://web.dev/articles/vitals)

## Redesign security and privacy

| Priority | Evidence and exposure | Release acceptance |
| --- | --- | --- |
| P0 · Public assistant abuse | Both function handlers accept anonymous POSTs and use the first forwarded-for value. The shared limit is 20 requests/minute per key in an in-memory map, with a full clear above 5,000 keys. Origin is checked only when present alongside Host. In a multi-instance deployment the code cannot enforce a global quota. Forwarded header trust depends on the production proxy. | Test trusted client IP handling and a shared or edge-backed limiter across instances and both APIs. Add global concurrency/spend caps, request and token budgets, and a kill switch. Confirm rejection occurs before any provider call. Treat Origin as a browser signal, with independent abuse controls. |
| P0 · Assistant input and upstream cost | Vercel handlers pass parsed bodies through without app-defined MIME or whole-request byte checks. The server trims selected fields and applies per-upstream timeouts. Model fallback can make multiple calls. | Enforce JSON content type, request size, schema, allowed keys and per-field limits at entry. Return appropriate 400/413/415/429 responses and use a total upstream deadline and retry budget. Verify malformed and oversized requests using local fixtures. |
| P0 · Privacy | The chat sends visitor questions and recent turns to Gemini. Page transformation sends page text. The browser stores recent messages in sessionStorage. Voice depends on browser speech recognition. | Explain what goes to which provider at the point of use. Keep the widget off account, payment and sensitive pages. Offer clear-chat, minimize retention and logs, redact high-risk identifiers before transfer where practical, and keep transcripts and credentials out of analytics. Confirm provider terms and data handling with the institution. |
| P0 · Assistant integrity and safe actions | Citations are checked against retrieved IDs and some fact patterns. This can miss misleading paraphrases or a number used out of context. Retrieved text can also carry prompt injection. Model actions are constrained to known actions, but a model response can still trigger an allowed action. | Derive navigation from deterministic explicit user intent, and display source links for ambiguous requests. Use validated records for fees, eligibility, deadlines and official contacts. Review ingestion, quarantine suspicious sources, and validate answer/action schemas and destination URLs independently of model output. Add stale-data and malicious-source fixtures. |
| P0 · Browser and transport headers | Local homepage response sent Content-Type with no app security headers. The checked-in Vercel config has no custom header policy. The homepage uses inline boot code. | On an authorized preview, inspect final edge responses. Roll out CSP in report-only first, then enforce with compatible script hashes or external boot code, restrictive framing, MIME sniffing protection, an appropriate referrer policy, permissions policy and HTTPS/HSTS aligned with subdomain ownership. Prevent API response caching. |
| P0 · Development server boundary | Local preview is loopback-only. Status-only checks returned 200 for package.json, assistant-server.mjs and knowledge/chunks.json and 404 for .env. The dev server serves eligible files from the project root. The production build has a narrower allowlist. | Keep preview loopback-only and publish only explicitly intended browser assets. Verify preview and production deny source, tests, raw index, caches and environment artifacts on the static origin. Check that raw deployment artifacts carry no secrets. |
| P1 · Data supply chain | Crawler follows redirects, caches successful pages and skips them on later runs when cache exists. It stops on human checks. | Enforce allowed schemes/hosts throughout redirects, response limits, freshness checks, reviewable content diffs, source provenance and rollback. Flag or suppress expired high-impact content. Keep keys server-side and scope them per environment. |
| P1 · Institutional publishing and operations | Current app is a prototype with official portal handoffs. A future CMS or new forms would add privileged workflows and data custody. | Require staff SSO/MFA, role-scoped access, approval history, secure recovery and review of uploads if introduced. Test backups, audit logs, rate-limit alerts, secret rotation and incident contacts. Create a vulnerability reporting contact. Keep login and payment handoffs on verified official hosts. |

Use OWASP ASVS to record app controls and the OWASP GenAI risk list to design assistant abuse tests. Evaluate WordPress and third-party portal configuration only with the institution's cooperation and an agreed test scope. [OWASP ASVS](https://asvs.owasp.org/) · [OWASP GenAI Top 10](https://genai.owasp.org/llm-top-10/)

## Release sequence and verification

1. **First release.** Add public navigation for Students, Exams & Results, Programme Finder, Safety & Support, Contact and Public Disclosures. Put verified India and International application links next to cycle and campus. Add skip navigation, privacy/accessibility links and safe fallback content. Keep the public assistant gated until abuse, data-handling and header controls pass in preview.
2. **Content parity.** Add International, campus/visitor, directory, career, library, news and event records. Review every link in the official inventory with a responsible office. Assign each legacy URL a destination, redirect, retained external link or retirement decision. Cover document accessibility and data expiry in the publishing checklist.
3. **Launch verification.** Run five end-to-end journeys on desktop and mobile: applicant finds the correct programme and applies, student finds the correct exam/portal route, visitor gets accessible directions, international student finds mobility or visa guidance, and public user finds the right disclosure year. Verify keyboard, screen reader, touch, 320 px reflow, slow network and fallback behavior. Capture preview headers, API boundary and rate-limit results, field-performance baseline when available, and migration link status.

P0 means a proposed launch gate for a public institutional redesign. P1 means the next content or operational release. The ordering assumes a public information site with official portals retaining transactions and private records.
